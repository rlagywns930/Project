## 프로젝트

### 01·02. 타이타닉 생존 분석 및 예측
- **문제:** 생존에 영향을 준 요인을 찾고 생존 여부를 예측한다.
- **방법:** Feature Engineering으로 일반화 성능을 확보하고, Random Forest·XGBoost 등 앙상블 모델을 비교했습니다.
- **해석:** SHAP으로 모델의 의사결정 근거를 분석했습니다.
- **결과:** Kaggle 기준 Accuracy 0.78

### 03. LSTM 기반 수위 예측 (졸업 연구, 교내 학술제 2등)
- **문제:** 센서 데이터로 만수위까지 남은 시간을 예측해 침수 가능성을 미리 알린다.
- **데이터:** 저비용 센서(HC-SR04 + Arduino)로 수위 데이터를 직접 수집하고 이상치 제거·정규화를 거쳐 정리했습니다.
- **방법:** 5개 수위 지점의 도달 시간으로 만수위까지 총 소요 시간을 예측했습니다. (LSTM, TensorFlow/Keras)
- **결과:** MAE 3.87초, RMSE 4.81초. 기준 시간 70초 대비 약 5~7% 오차입니다. 예측값이 기준 시간보다 짧으면 침수 가능성을 경고하는 판단 로직을 구현했습니다.
- **한계:** 실내 소규모 실험이라 샘플 수와 환경 다양성이 제한적이며, 실제 환경 적용에는 추가 검증이 필요합니다.

### 04. 미국 주택 가격 분석 및 예측
- **문제:** 주택 가격에 영향을 주는 변수를 찾고 가격을 예측한다.
- **방법:** 변수 스케일링, 로그 변환, 이상치 제거로 학습 파이프라인을 정리하고 여러 회귀 알고리즘을 비교했습니다.
- **결과:** RMSLE 0.1116

### 05. 남자 가을 패션 트렌드 분석
- **문제:** 정답이 정해져 있지 않은 비정형 텍스트에서 패턴을 찾아 트렌드를 분류한다.
- **방법:** LDA 토픽 분포와 TF-IDF를 결합한 입력을 설계하고, GridSearchCV로 튜닝했습니다.
- **결과:** XGBoost 성능 4.3%p 향상. 고차원 텍스트 데이터에서 트렌드 분류 자동화의 가능성을 확인했습니다.

### 06. 5515번 버스 수요 데이터 분석 (2026.07 ~ 2026.08, 팀장)
- **문제:** 5515번 수요가 어느 시간·구간에 몰리는지 확인하고 운행 개선안을 제안한다.
- **분석:** 서울시 공개 데이터 12개월(2025.07~2026.06)을 분석해 5515번 수요가 학기 중 평일 오전에 집중됨을 확인했습니다. 367개 노선 중 운행대당 월평균 승차 3위, 오전 8시 수요 최고였고, 인접 노선(5511·5517 등)과 비교해 서울대입구역 2번 출구 하차 비중이 가장 높았습니다.
- **제안:** 5515번은 유지하고, 학기 중 평일 07:20~09:10에 맞춤형 버스를 4주간 시범운행. 수요·서비스·운행·만족도 지표로 정례 운행 여부를 판단합니다.
- **한계:** 혼잡률·환승·이동 경로(OD) 자료가 없어 "공급 부족 확정"이 아닌 "수요 집중 확인"으로 결론을 제한했습니다.
- **역할:** 가설(H1~H5) 분담, 진행 상황과 회의 결과를 Notion에 매일 정리, 최종 결과 발표 담당
- **사용 기술:** Python, Notion

### 07. 채용 플랫폼 사용자 행동 분석 (2026.09 ~ 2026.10, 팀원)
- **문제:** 같은 관심 분야의 구직자도 지원 방식이 다르다. 행동 유형을 나누고 유형마다 필요한 지원 경험을 찾는다.
- **데이터:** 지원자 10,287명(2022~2023), 로그 약 1,724만 건, 지원·공고·북마크 데이터
- **분석:**
  - 대량성·집중성·다양성·공고 탐색성·북마크 탐색성 5개 지표를 **데이터 분포에서 기준값을 산정**해 설계했습니다. (다양성 지표 설계 담당)
  - 충족한 신호 수로 G0(63.0%)·G1(28.6%)·복합(8.4%)으로 나누고, 복합 신호는 A·B·C 3개 유형으로 세분화했습니다.
  - 로그 퍼널·세션 분석으로 그룹마다 지원 흐름이 달라지는 지점을 확인했습니다. **그룹을 나눈 기준과 겹치는 지표는 근거에서 제외**했습니다.
- **인사이트와 제안 (그룹별 1개, 모두 A/B 테스트로 검증할 가설)**

| 그룹 | 발견 | 제안 |
|:---:|:---|:---|
| G0 | 공고 조회 후 지원 시작이 이어지지 않은 비율 34%, 그 뒤 약 74%가 다른 공고를 계속 탐색 | 최근 본 공고를 한 화면에서 비교하는 후보 비교판 |
| G1 | 작성 중 멈춘 뒤 돌아온 사용자의 96~99%가 처음부터 다시 시작 | 멈춘 단계로 바로 복귀 |
| A | 하루 지원이 많을수록 지원 1건당 상세 조회가 줄어듦(4.0회 → 0.67회) | 여러 공고를 한 화면에서 확인하고 지원하는 일괄 확인 |
| B | 지원 직전 기업 정보 확인 41%(G0 49%) | 지원 직전 기업 핵심 정보 한 줄 노출 |
| C | 한 세션에 5건 이상 지원하는 비율 28.5%로 가장 높음 | 지원 완료 직후 신규 공고 이어주기 |

- **한계:** 로그의 공고 ID가 가려져 공고 단위 분석이 어려웠고, 채용 결과를 알 수 없어 행동 차이만 확인했습니다. 제안의 효과는 후속 실험이 필요하며, A·C는 표본이 작아 가설로 해석합니다.
- **사용 기술:** Python, SQL, Pandas, 통계 검정(t-검정, ANOVA)

## 분석할 때 지키는 원칙

- **문제에서 시작합니다.** 모델 성능보다 "무엇을 알고 싶은가"를 먼저 정합니다.
- **기준을 데이터에서 찾습니다.** 임계값은 분포를 보고 정하고, 근거를 남깁니다.
- **근거를 점검합니다.** 그룹을 나눈 기준과 겹치는 지표는 근거로 쓰지 않습니다.
- **상관과 인과를 구분하고 한계를 씁니다.** 제안은 검증 가능한 가설로 제시합니다.
